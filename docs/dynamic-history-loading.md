# 动态历史加载：分块正文与完整索引

[English](dynamic-history-loading.en.md) · [架构](architecture.md)

> **2026-11-02 用户确认目标**：最初的问题是长对话加载卡顿；最终方向是彻底优化
> TUI 对话加载架构——**动态分块加载、分块索引**，不只是修右侧栏。
> 后续不能以恢复全量正文投影来换取索引完整或跳转正确。
> **本轮实现与验收已完成**：102 项 build gates、类型/包检查、36 项真实 channel + Chat
> 集成、124 块真实会话 seed-shape 和隔离 profile 安装均通过。证据与启动相位见交付目录

## 1. 为什么需要两层

仅限制渲染行数不够：如果首屏前仍把全部日志投影为正文行，再折叠/虚拟化，
昂贵的文本处理、工具结果呈现已经发生。另一方面，正文尚未加载不代表那段会话不存在。

| 之前的错误 | 约束 |
| --- | --- |
| 旧块里伪造一排 `user` 占位行，屏幕看起来只有提问、没有模型输出 | 未加载正文每块只显示一行摘要；提问目录是非渲染元数据 |
| 摘要取代旧用户行后，rail 只剩最新几轮 | 索引覆盖全部真实用户轮次，与正文是否物化无关 |
| 点一次索引触发全量正文重投影 | 一次 reveal 只投影目标所属块，不展开全记录 |
| 用估算行高挑块、提前丢掉 seek 锚点；新位置越过旧 `maxScroll` 后被误当贴底 | 用实测几何选可见块；显式 seek 与跟随底部区分，测量收敛后再完成跳转 |

```text
真实会话日志（不修改）
  └─ 翻译、分块计划
       ├─ 轻量目录：全部用户 turn 的身份、提问文本引用/预览、图片数量
       │    └─ rail：完整顺序、悬停预览、未加载 turn 的 reveal handle
       └─ 正文块：首屏只物化最新块
            ├─ 旧块：一行 notice 摘要 + 非渲染 collapsedTurns 元数据
            └─ 按需物化：摘要原位替换为块标题及真实用户/模型/工具行
```

目录逻辑上完整，不意味着在有限高终端同时画出数千个 tick；rail 仍按原有视口窗口展示。
加载后真实用户行替代对应目录项，不能重复计数。`/clear`、新会话或会话切换必须清理或
重建块计划、handle 映射及预览缓存，不能复活前一个会话的索引。

## 2. 边界与预算

真源始终是后端持久化日志；投影只改变**何时呈现**，不删除、压缩改写或伪造会话事实，
也不重新执行历史工具。块正文继续经过共享投影器。

| 项目 | 当前规则 |
| --- | --- |
| 最新块 | `OPEN_ROUNDS = 2`，`OPEN_CHARS = 200_000` |
| 更早块 | `CHUNK_ROUNDS = 50`，`CHUNK_CHARS = 1_000_000` |
| 切分 | 从最新往旧分组，只在 `user.message` 的轮边界切；整轮不能拆开 |
| 超重轮 | 单轮超过预算时独占一块，不截断内容；预算不是硬内存上限 |
| 权重 | 提问、模型文本、工具参数/结果等字符串的字符长度，不是磁盘字节数 |

切块计数包含 injected/goal、compaction 等 `user.message`，防止长无人值守过程成为单一巨块；
**用户轮次索引**则匹配真实用户行的可见谓词：`source === 'user'`，且文本非空或含图片。
纯图片提问算一轮；team-message、注入上下文、压缩检查点与命令输出不冒充用户轮次。

默认开窗刻意小到「最近两轮」：首屏只需要投影末尾交换，阅读者一落地就在最新轮次。
更早的每一轮仍是 rail 上的一格刻度 / 一行摘要块，点击即投影它所属的那一块（见 §5），
所以少开不是丢内容，而是把「投影成本」推迟到读者真的要看它的那一帧。

## 3. 索引身份与精确 reveal

摘要行的 `collapsedTurns` 保存 `{ id, seq, text, imageCount }`；它不是正文 `ChatRow`。
虚拟 `id` 是导航 handle，不是猜测出来的投影行偏移。当前命名空间位于所有块行 id 以下：

```text
oldestIdBase = chunk.idBase - chunk.index * ID_STRIDE
handle = oldestIdBase - globalEntryIndex - 1
handle → { chunk, durable seq } → 物化这一块 → seq 对应的真实用户 row id
```

事件下标不等于正文行下标：隐藏输入、工具卡等都会改变行数。点块中第二条提问必须落到
第二条真实提问，不能只返回块标题或首条提问。块物化后保留旧 handle 别名直到下一次
seed/clear，让自动加载前已绘出的 tick 仍能定位同一 `seq`。

## 4. 按需加载与导航几何

- **Load on sight**：滚动后，在提交后的 Yoga 实测位置中，挑实际视口内最靠近中心的摘要。
  仅 overscan 挂载但不可见的摘要不能触发加载。当前停留延迟为 `120 ms`；一次滚动手势
  至多自动展开一块，跟随底部时不触发。延迟不是端到端完成时限。
- **Rail reveal**：点击未加载 turn，通过上述映射只物化所属块，再 force-mount 与 seek；
  物化后必须发布状态，不能等下一次键盘/滚轮才重画。
- **Navigation proxy**：未加载 turn 可暂借所属摘要的 top 判断相对位置，但不能直接
  `scrollTo(proxyTop)` 代替 reveal。先跳到旧块后，另一个未加载块可能在视口**下方**，
  所以 `folded` 不能一律解释为“在上方”。同摘要的多轮共用代理 top：上方取末轮作 ▲，
  下方取首轮作 ▼；代理不伪造 sticky prompt。真实尾部不可达的 prompt 仍受 `maxScroll` 约束。

## 5. 测量收敛后的 seek 握手（已验证）

1. 解析真实目标 id，保留 `forceMountRowId`，使目标进入虚拟化挂载窗口。
2. `MessageList` 完成行高/前缀测量，且无待处理的测量修正后，调用
   `onSeekReady(rowId, textOffset)`；offset 取目标自身的 prompt margin，不缓存旧几何。
3. `Chat` 用新鲜 Yoga top 加 offset 对齐；以 `min(targetTop, maxScroll)` 确认可达落点。
   不可达的尾部 tick 不能因“永远无法到顶”陷入重复 seek。
4. 只有渲染器已消费 seek、滚动位置确实对齐后，才延后释放 force-mount。
   不能在 ref 刚出现时就宣告完成，也不能用更长的固定等待替代几何确认。
5. 用请求身份与显式滚动 intent 版本保护握手：新的滚轮、End 或索引跳转取消旧请求；
   同会话 rebind 也按 binding generation 清理。纯布局修正不是用户导航，无关流式尾部不阻塞旧块 seek。
6. 显式元素 seek 那一帧不按**旧** `maxScroll` 重新判为贴底；摘要变为真实正文后的
   高度增长不是用户主动返回底部。测量继续调整时，仍须保持同一提问锚点。

## 6. 开销边界：没有端到端常数时间/内存承诺

本架构推迟旧块正文投影、工具结果呈现和挂载；**宿主仍全量解压、解析、校验日志**，
当前翻译、分块规划、目录与全会话用量统计也仍有随历史增长的工作，并持有记录/引用。
这不是从磁盘随机读取一个块的宿主架构改造。

历史测量在约 93k 事件样本上记录过首帧从 16.7–17.3 s 降到约 12–13 s；更大沙箱快照
也出现过约 15 s。它们是不同快照/构建的旧证据，**不能作为本轮新索引/seek 已通过的证明**，
更不能宣称已达到 2 s；阶段拆解应看 `DSH_TUI_BOOT_TRACE`。

**已加载块目前没有 LRU 卸载**：浏览更多块会累积真实正文行。渲染虚拟化只限制挂载，
不等于释放已投影正文、原日志、翻译记录或索引。不能写成“端到端常数内存”，也不在本轮
另加缓存/宿主方案以扩张范围。

### 6.1 点击索引的真实成本与三处优化

`scripts/perf-rail-click.tsx` 在真实 DSH channel、生产 fullscreen `Chat` 和无头 xterm 上重复
「点击未加载 turn → 被点提示行出现在顶部 → 200 ms 后仍在原位」的闭环。夹具为 372 块 / 368 个
人类轮次（重形状每块约 22 行、20 次工具调用），并断言该次点击真的触发了 `revealRow`
（用返回值判身份，不再靠摘要行数差推断，避免折叠窗口重绘造成的假样本）。

点击后的主线程被一段同步工作占满；拆开看是三处成本，本轮全部修掉：

1. **同步物化里的记账**。`revealRow` 内部的块级 projection 对每条工具结果做 token 估算，
   纯为记账却把整段文本从头扫一遍。`AgentEventMeta.scratch` 让块级 replay 跳过这些估算
   （`projection.ts` 的 `countTokens`），`revealRow` 的同步段从 28–61 ms 降到 **2–4 ms**。
2. **摘要预览切片**。`preview` 原先要摊平整串再截断；改为有界倍增窗口扫描（`transcript.ts`），
   大工具结果上的摘要不再按全长收费。
3. **布局缓存槽位**。一次 reveal 会在同一帧挂载整块卡片（约 1.2k 个 Yoga 节点）。
   `src/native-ts/yoga-layout` 的跨代布局缓存每节点只保留 4 组输入，而新挂载的卡片在一次
   pass 里会用超过 4 组宽度/模式探测，LRU 在探测重复前就绕回，1.6k 节点的树被访问 10 万次。
   提高到 8 组后 `layoutNode` 访问 102,524 → 29,746、文字测量 30,847 → 6,254；16 组无额外收益，故停在 8。

实测（同字节夹具，5 次点击 × 2 轮取中位；点击 → 稳定落地）：

| 形状 | 指标 | 修前 | 修后 |
| --- | --- | --- | --- |
| 每块 1 行 / 1 次工具调用 | 落地 p50 / p95 | 363 / 592 ms | 329 / 540 ms |
| 每块 22 行 / 20 次工具调用 | 物化 p50 / p95 | 319 / 612 ms | 245 / 502 ms |
| 同上 | 落地 p50 / p95 | 367 / 1138 ms | 308 / 845 ms |

口径：墙钟时间，包含无头 xterm 在同一进程里解析这一帧输出；真实终端写屏更便宜，因此上表偏保守。
剩余成本集中在「整块卡片在同一帧里首次挂载」，渐进挂载会改变落点几何，本轮不扩大范围，留作后续。

### 6.2 默认只摊开「用户说了什么」和「模型说了什么」

**问题**：块一展开，整块历史就按正文全画。真正撑起行数的是低内容密度的大字段——代码块
（一个 120 行围栏就是 120 行）、思考段、工具卡、多行命令脚本、长表格。用户实际阅读的是
「用户输入句 + 模型文字回答句」，其余都应在展开块里默认收成一行摘要。

**做法**（`MessageList.tsx` + `Markdown.tsx` + `TranscriptLeaves.tsx`）：

- 已结算的助手文本里，顶层代码围栏改画一行摘要：
  `⌁ ts · 26 行 · const marker = … … （点击展开）`。摘要不进 `CodeBlockFrame`，
  也不做高亮/换行测量；点摘要行或者点展开后的代码块都能来回切换（点击是
  「按下未拖动」的 release，拖选复制代码不受影响）。`Ctrl+O` 仍然整体展开。
- 还原行（`row.restored`，即 revaled 块与窗口上限回补的行）默认把终端卡标题折成首行 +
  `… +N 行`，与既有的工具结果 3 行上限、思考 1 行摘要同一套语义。
- 流式行（`row.streaming`）永远不折：折叠只作用于已结算内容，否则会看到文字反复伸缩。

**实测**（`ASSISTANT_KB=6 RESULT_KB=300 CALLS=3 CMD_LINES=8`，187 块，同字节夹具对照）：

| 指标 | 折叠前 | 折叠后 |
| --- | --- | --- |
| 单帧 Yoga 测量节点数（3 次点击） | 5854 / 7477 / 7513 | 3830 / 3758 / 3710 |
| 物化 p50 / p95 | 190 / 245 ms | 193 / 372 ms |
| 落地 p50 / p95 | 328 / 534 ms | 342 / 604 ms |

口径：把「折叠」开关做成同一构建内的运行时开关（已在实验后移除），夹具相同、轮次相同。
Yoga 测量节点数减半说明上屏成本确实降了；但在这个夹具里点击墙钟被两件与折叠无关的事主导
——块级 projection 与无头 xterm 解析整帧输出——所以 p50/p95 落在 ±100 ms 噪声内，不能据此
宣称端到端变快。真实收益体现在「一屏里现在真的要画的行数」：120 行围栏 → 1 行。

**隔离验证**：`dsh-sandbox` 的 manual profile 装本轮 tgz，`--new` 会话让模型回一个 38 行
python 围栏，屏上只有 `● ⌁ python · 38 行 · import random … （点击展开）`；点击后出现完整
围栏，再点代码块收回摘要。集成侧 `scripts/verify-chunked-rail.tsx` 增加 6 项断言（摘要上屏、
默认不画正文、Ctrl+O 来回、点摘要展开、点代码块收回），36 项 → 42 项全过。
